1 · Identity — what the repo IS

Shape

Harness, not app

It reshapes how Claude Code behaves in your sessions — slash commands, permission rules, pre-tool hooks, cost logging. No service to deploy.

Foundation

Built on superpowers

The official superpowers plugin is the skill engine. claude-damn adds opinionated modifiers, review ladders, and harness guards on top.

A11y

Accessibility is load-bearing

Treated as a first-class design concern, not a post-hoc checklist. Skills prefer structured prompts over disruptive modals, avoid involuntary focus or tab shifts, and keep rejection semantics honest — a denied step is a question, not a conclusion.

Discipline

Disciplined git + isolation

Commits are deliberate and reviewable. .worktrees/, .checkpoints/, and .remember/ keep per-branch work and session state out of the main tree.

2 · Skill composition — four modifiers stack

Every workflow name is a combination of four building blocks. Read the name left-to-right and each modifier adds one behavior to the pipeline.

Modifier vocabulary
Modifier What it adds Flag it flips
super Brainstorm requirements before implementing Planning phase ON
duper Run inside an isolated git worktree Workspace isolation ON
cat Fan out to parallel subagents Subagent execution ON
tdd Red–green–refactor discipline Test-first ON

Four families emerge from the combinations:

  • TDD — /tdd, /tdd-cat, /duper-tdd, /duper-tdd-cat
  • Brainstorm + TDD — /super, /super-cat, /super-duper, /super-duper-cat
  • Debug + Brainstorm + TDD — /super-fixer … /super-duper-fixer-tdd-cat
  • Expert Review — /expert-review through /expert-super-duper-tdd-cat-review (10 variants)
Reading a name: /expert-super-duper-tdd-cat-review = expert review → brainstorm → worktree → TDD → parallel subagents. Top of the ladder; reserve for work that actually needs every modifier.

Beyond the combinators there are utility skills: /checkpoint-save, /checkpoint-resume, /check-yourself, /cost_, /cost-opt, /listen, /proceed, /sync, /tesseract, plus PR-feedback and fast-review skills.

4 · Harness systems — runtime behavior

settings.json

Permission guards

Granular allow / ask / deny lists: blocks destructive gh ops, gates git commit, protects settings files. Deny-by-default on anything scary.

hooks/block-inline-scripts.py

Inline-script hook

PreToolUse Bash guard. Denies over-long commands or too many chained statement separators, forcing multi-step work into separate calls or /tmp/ scripts.

src/extract_cost.py · /cost_

Cost tracking

Parses session JSONL for real usage fields and computes spend via Anthropic pricing. /cost-opt compacts logs and surfaces routing suggestions.

.checkpoints/ · /checkpoint-{save,resume}

Checkpoint system

Save resumable context per branch, with automatic archive rotation. Paired with .remember/ for session-to-session continuity.

Model routing: Sonnet for reads, config edits, short Q&A. Opus for multi-file refactors, subtle runtime bugs, new API/data-model design. This routing is exactly the cost lever quantified in the rtk-evaluation tab.

rtk — Rust Token Killer: an independent evaluation

Security, competitive position, and the real token / cost ROI of rtk — including how it stacks with claude-damn on pay-as-you-go API pricing. Synthesized from parallel sub-audits of the public repo.

Rust · single binary · ~78k LOC Apache-2.0 · v0.42.x 65.7k★ · weekly releases 14 agent integrations · 100+ commands

The verdict  ADOPT — WITH CAVEATS

Install rtk for the one job it does well: compressing noisy build / test / git output that flows through the Bash tool. Don't expect the headline 60–90% — realized savings are workflow-dependent. The bigger lever for a pay-as-you-go user isn't rtk at all; it's model routing (claude-damn's territory). Used together they multiply.

SECURITY

Execution core is sound (argv, no sh -c). The secret-exposure items are in the output layer — and most are already tracked by the maintainers, with a fix PR in flight.

POSITION

Clear category leader for live-output compression. One rival (squeez) covers the Read/Grep/Glob path that rtk's Bash-only hook structurally can't.

ROI

rtk alone ≈ 10–22% fewer tokens. With claude-damn routing, combined API-cost savings ≈ 20 / 37 / 54% (conservative / expected / optimistic).

What it is & how it works

rtk installs as a Claude Code PreToolUse hook. It rewrites a shell command, runs the real tool itself, then returns filtered / compressed output to the model. Four strategies: filtering, grouping, truncation, deduplication.

Token ROI — how much you actually save

rtk's vendor benchmark (−80% on a 30-min session) assumes you route cat / grep / find through Bash. Many Claude Code workflows don't — they use native Read/Grep/Glob, which already produce compact output and bypass rtk's hook. That removes ~34% of rtk's headline number before you start.

Flat-rate plans (Pro / Max)

Dollar savings ≈ $0 — you've already paid. The value is daily-cap capacity: ~10–22% fewer tokens ≈ ~11–28% more work before the cap, and fewer mid-session rate stalls.

Pay-as-you-go (API)

Savings are real dollars — but rtk only cuts the output-token slice, so the whole-session figure (10–22%) is far below the per-command claim. The next section adds the bigger lever.

Where rtk earns its keep either way: git status/diff/log, pytest, ruff, cargo, npm test — exit-path dumps the auto-rewrite hook cleans up with zero habit change.

rtk + claude-damn together (API pricing)

claude-damn's cost levers are orthogonal to rtk's, which is why they stack:

rtk — cuts token volume

Compresses command output (mostly the output side). Bash-only.

claude-damn — cuts price per token + carried context

Routes routine work to Sonnet/Haiku, reserves Opus for hard reasoning; isolates exploration into subagents so the main thread never carries it; trims context with targeted reads. Model-side, not output compression.

Security posture

Verdict: reasonable hygiene for its class. The part that matters most for a hook — that it won't silently run something different — is solid. The exposure is secrets, in the output layer, and the maintainers are already on most of it.

Operational notes — and their tracking status

Findings from an independent source review, with rtk's own issue-tracker status. "Harden" = a gap; "By design" = expected behavior worth knowing.
Kind Note rtk status
HARDEN tee files & tracking.db are world-readable (0644); the DB stores full commands + project path Tracked #1790, #1160 · fix in PR #656
HARDEN rtk env masks on a variable-name denylist; values aren't inspected, so DATABASE_URL=…pw can print in full Tracked #2271 / #1875
BY DESIGN aws secretsmanager get-secret-value prints the secret (that's the command's job) Tracked #1875
BY DESIGN rtk curl / wget pass response bodies through unredacted (fidelity over redaction) — tokens in a JSON body reach the model Novel (low-sev)

GENUINE STRENGTHS

Argv execution, never sh -c · conservative passthrough on shell constructs it can't safely decompose · least-privilege permissions (default = ask) · checksum-verified, path-traversal-guarded installer · telemetry default-OFF, anonymized, env-overridable · salt file already 0600 · unsafe_code = "deny" · parameterized SQL · active security-issue triage.

RESIDUAL RISK

The execution core is trustworthy; the exposure is secret-on-disk (tee / tracking DB at 0644) and secret-to-model (env / curl / aws). With a single trusted user the disk angle is low-impact. Don't rely on the "strips secrets" claim — verify per command.

What to actually do

  • Install the global hook and let it auto-catch git / test / lint / build — ~80–85% of the realizable win, zero habit change.
  • For real dollar savings, pair it with model routing (Sonnet/Haiku for routine work). On a pay-as-you-go plan, routing is the bigger lever; rtk is the multiplier on top.
  • Don't re-route Read/Grep/Glob to rtk read/grep — native tools are faster, lossless, and bypass the hook anyway.
  • Treat rtk env / curl / aws secretsmanager as NOT secret-stripping. Don't run them against credential-bearing sources expecting redaction.
  • Tee: fine where the host has a single trusted user; disable via [tee] mode = "never" before using it on a shared host. Telemetry is off by default.
  • Pin a version and verify release checksums — you're putting a binary in an autonomous agent's command path.
  • Measure, then re-decide. Run a week, check rtk gain, keep it if the bump is real. If the Read/Grep gap nags you, trial squeez.
